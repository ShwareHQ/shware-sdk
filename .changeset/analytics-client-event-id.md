Generate event ids on the client and fire the pixels when an event is tracked.

- **Client-generated uuidv7 event ids in the DTO.** `track()`, `trackOnce()` and `trackAsync()` give every event a uuidv7 when it is tracked and send it as `id` in each event of `POST /events`. `createTrackEventSchema` reads it as an optional, version-7-checked uuid — and now checks `visitor_id` and `session_id` as version 7 too, since all three are generated by the SDK, so servers need not re-validate them — so batches from older clients (without `id`) still parse; servers use the client's `id` when present and generate one otherwise. `onSucceed` reports this id.
- **Pixels fire at enqueue time with the same event id.** Third-party trackers are called synchronously inside `track()` with the event id (Meta `eventID`, Reddit `conversionId`, LinkedIn / UET / OpenAI `event_id`) instead of after the server's answer. Events followed by a full-page navigation (outbound links, `begin_checkout` before a payment redirect, a landing page left at once) and events sent by beacon on `pagehide` / `visibilitychange` now reach the pixels; beacons fire nothing again. The conversions APIs, sent under the stored id, still deduplicate against them. `trackAsync` keeps resolving after the server answers, but is no longer needed before a navigation to keep the pixels. `trackOnce` reuses the id of an attempt that failed to send (kept under `track_once_attempt.<event>`), so a retried key fires no pixel twice.
- **Servers should dedupe on `id`.** Insert events with `on conflict (id) do nothing`: the batch POST is retried on network errors, 408, 429 and 5xx, and a batch the server committed but whose answer was lost is then stored once instead of again. The retry policy itself is unchanged.

The `POST /events` answer (`TrackEventResponse`, one `{ id }` per event) is no longer read: any 2xx is a stored batch. Servers should keep answering it while clients before this version, which fire their pixels with those ids, are in use; it can be dropped in the next major.
