Journey messages are now delivered **at most once**. A copy is _claimed_ (`message.claimed_at`, committed just before the transport takes it) between `messagePrepared` and the send; a replayed send step that finds a copy claimed but never settled treats it as possibly delivered and does not send it again (a warning names the idempotency key). A send that fails for sure — a thrown send, a 5xx, a 429 — releases the claim, so the step's retry still sends it, as before; a settled copy is still skipped. Exactly-once is not possible: Cloudflare Email Service (the `send_email` binding and the REST endpoint) and SES accept no idempotency key or client message id, and FCM does not de-duplicate; between the options left, a duplicate marketing email costs spam complaints, unsubscribes and sender reputation while a lost nudge is invisible and the journey has later steps (the Customer.io / Braze behaviour). Templates that must arrive opt into at-least-once per template with `redelivery: 'resend'` (email, push, Slack, Discord; the default is `'skip'`). See the README's "Delivery guarantee". The comments on `cloudflareEmailTransport` and `EmailBindingLike.idempotencyKey` that said the binding de-duplicates on the key were wrong and are fixed; the key is still passed.

`JourneyObserver` gains the optional `messageClaimed` / `messageReleased`, and `JourneyReporting` the `claimMessage` / `releaseMessage` the Postgres store implements. **Hosts must migrate:** `message` gains a nullable `claimed_at` column — regenerate the drizzle file (`workflow-ui generate`) and run the migration before deploying; it needs no data step, and `POST /bundle/deploy` refuses to run until the column exists.
