One flat `workflow.config.ts` for the whole project: `defineConfig({ title, contract, workflows, segments, actions, templates: { email, push }, emails: { from, replyTo }, runtime, apns, fcm })` registers everything once — what is deployed, the template registries, the contract, the email envelope and how the engine runs per mode. `compileConfig(config)` builds the bundle with the template manifest taken from the registries and checks every message node (an unregistered or cross-channel template, a literal prop the schema refuses, a missing required prop, a user ref the contract's profile does not declare → `ConfigCompileError` naming the workflow and node). `journeyWorker({ config, store, devices })` serves that bundle at `/bundle` and `/bundle/deploy`, assembles the email sender, the per-platform push senders (`ApnsPushSender` for `ios`, `FcmPushSender` for `android`), the template validator, `/preview` and the runtime from it, and validates ingest with its contract. Secrets come from the environment under fixed names (`APNS_PRIVATE_KEY_BASE64`, `GOOGLE_APPLICATION_CREDENTIALS_BASE64`, `API_TOKEN`, dev-only `APNS_RELAY_ORIGIN`) and `ENVIRONMENT` picks the mode. Template keys are unique per channel, so an email and a push may share one.
