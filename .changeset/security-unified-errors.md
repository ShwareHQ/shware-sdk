The JSON login routes (native, One Tap, email, desktop) now answer every failure they know with one google.rpc error body, so a client branches on `ErrorInfo.reason` everywhere and the host's error handler only sees server faults. What changed on the wire: a wrong or exhausted email code is `403 PERMISSION_DENIED` (was 400); a missing or replayed One Tap / native nonce is `403 NONCE_MISSING` / `NONCE_MISMATCH` (was a raw `{ error: 'invalid_request', error_description }` with 401 or 400); a bad `code_verifier`, `attributes`, content type or non-JSON body is `400 INVALID_ARGUMENT` with a reason (`INVALID_CODE_VERIFIER`, `INVALID_ATTRIBUTES`, `INVALID_CONTENT_TYPE`, `INVALID_JSON`) instead of a raw OAuth2-style body or a 500; an `OAuth2Error` from the provider client is answered by what it means (`400` for a malformed request, `403` for a refused code or token, `503` for a provider outage) with `OAUTH2_<error>` as the reason instead of propagating to the host; `EMAIL_DELIVERY_FAILED` is `503 UNAVAILABLE` (was 400); a desktop code with the wrong verifier is `403 INVALID_DESKTOP_CODE` (was 400). An id token that fails verification is now an `invalid_grant` `OAuth2Error` (was `invalid_request`), so the redirect flow reports it as such. Removed: the never-implemented `loginPhone`, `sendPhoneVerificationCode`, `PATH.LOGIN_PHONE` and `PATH.SEND_PHONE_VERIFICATION_CODE`; the `EmailCodeVerification` type. `AuthService` now declares `desktopAuthorize` and `desktopExchange`. `oauth2Authorization` answers an unknown provider as `400 OAUTH2_INVALID_REQUEST` instead of throwing. `errorResponse(error)` is exported for the host's error handler, so a flow that calls `Auth` directly answers its errors the same way.
