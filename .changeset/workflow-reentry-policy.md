Add a per-workflow re-entry policy. Breaking, with no migration of old ledger rows or stored IRs: hosts reset or migrate the engine's data as they see fit. `workflow()` now requires `reentry`: `{ mode: 'never' }` (a user enters once), `{ mode: 'after_exit', cooldown? }` (again once their previous instance ended) or `{ mode: 'concurrent', cooldown? }` (again while one still runs); `cooldown` is measured from the previous entry. A missing policy, `never` with a cooldown or an unknown mode fails to compile, and `toIR()` refuses them at runtime. The IR is version 3 with a required `reentry`, so every content hash changes. The entry ledger holds one row per entry: `entry`'s primary key moves to `instance_id`, it gains a NOT NULL `occurrence` (the event id, or `$segment:<segment>:<since>` for a segment qualification) with a unique index on `(workflow, user_id, occurrence)`, so a redelivered trigger enters at most once in every mode and a segment trigger re-enters only on a fresh qualification; failed entries never block and never start a cooldown. `trigger` and `segment_trigger` gain a NOT NULL `reentry` jsonb, so an entry is decided without reading the IR. Store API: `TriggerRoute` / `SegmentTriggerRoute` carry `reentry`, `EntryInput` takes `occurrence` and `reentry`, `enterJourney` returns `'entered' | 'reclaimed' | 'duplicate' | 'refused'`, `getEntry(workflow, userId, occurrence)` takes the occurrence, and `pendingSegmentStarts` returns `{ workflow, since }[]`. Hosts add `reentry` to every `workflow()`, regenerate the drizzle schema (`workflow-ui generate`) and generate a migration.
