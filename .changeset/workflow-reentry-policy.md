Add a per-workflow re-entry policy. `workflow()` now requires `reentry`: `{ mode: 'never' }` (a user enters once, the previous behaviour), `{ mode: 'after_exit', cooldown? }` (again once their previous instance ended) or `{ mode: 'concurrent', cooldown? }` (again while one still runs); `cooldown` is measured from the previous entry. A missing policy, `never` with a cooldown or an unknown mode fails to compile, and `toIR()` refuses them at runtime. `WorkflowIR` gains `reentry` (absent in an IR stored before means `never`), so every workflow's content hash changes. The entry ledger changes from one row per `(workflow, user_id)` to one row per entry: `entry`'s primary key moves to `instance_id`, it gains a nullable `occurrence` column (the event id, or `$segment:<segment>:<since>` for a segment qualification) and a `UNIQUE NULLS NOT DISTINCT (workflow, user_id, occurrence)` constraint, so a redelivered trigger still enters at most once in every mode, and a segment trigger re-enters only on a fresh qualification. Store API: `EntryInput` takes `occurrence` and `reentry`, `getEntry(workflow, userId, occurrence)` takes the occurrence, and `pendingSegmentStarts` returns `{ workflow, since }[]`. Hosts must add `reentry` to every `workflow()`, regenerate the drizzle schema (`workflow-ui generate`) and generate an incremental migration; existing rows stay valid with no data step (README "Upgrading to 11.0").
