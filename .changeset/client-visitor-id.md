The visitor id is generated by the SDK (a uuidv7 kept in `config.storage`, `visitorId()`) instead of by `POST /visitors`, so a new visitor's first events — and the beacon of a visit left within a second, `session_start` included — no longer wait for a round trip and are no longer lost when the page goes first. Events never wait for the visitor: `getVisitor` only PATCHes the tags once per page and reads back the server's view (`distinct_id`), and that PATCH carries `device_id`, `platform` and `environment` for a server to create the visitor with. An id a server issued to an older client is kept. **Breaking: the server must create visitors from `POST /events` and `PATCH /visitors/:id`** (README, "Visitors"); deploy it before upgrading clients. `POST /visitors` is no longer called.
